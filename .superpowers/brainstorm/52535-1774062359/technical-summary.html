Lógica do proxy.ts (Atualizado)

// Rotas públicas — sem verificação
const PUBLIC = ['/login', '/register', '/api/auth']

// Rotas que precisam de sessão, mas NÃO de org ativa
const AUTH_ONLY = ['/onboarding', '/select-org', '/accept-invitation']

export default function proxy(request) {
  // 1. Rotas públicas → passa
  if (isPublic) return NextResponse.next()

  // 2. Sem sessão → /login
  if (!sessionToken) return redirect('/login')

  // 3. Rotas auth-only → passa (tem sessão)
  if (isAuthOnly) return NextResponse.next()

  // 4. Sem org ativa → /onboarding ou /select-org
  if (!activeOrgCookie) return redirect('/select-org')

  // 5. Tudo OK → acesso normal
  return NextResponse.next()
}

Nota: O proxy.ts só faz check otimista via cookies. A validação real (membro ativo, org existe) acontece no tenant-middleware do server.

APIs Utilizadas (Better Auth Organization Plugin)

Ação Client Method Endpoint Usado em
Criar org organization.create() POST /organization/create /onboarding
Setar org ativa organization.setActive() POST /organization/set-active Onboarding, Switcher, Select
Listar orgs do user organization.list() GET /organization/list Switcher, Select-org
Aceitar convite organization.acceptInvitation() POST /organization/accept-invitation /accept-invitation
Invites do user organization.listUserInvitations() GET /organization/list-user-invitations Pós-registro (check)

Ponto de Atenção: Roles

Better Auth usa 3 roles: owner, admin, member
Nosso sistema usa 5 roles: OWNER, ADMIN, MANAGER, COMMERCIAL, VIEWER

Solução: Configurar o plugin organization({ roles: {...} }) para aceitar nossos 5 roles customizados, ou usar o campo role da tabela Member diretamente via Prisma (já existe no schema). A segunda opção é mais segura pois nosso CASL já usa o role do Member.

Decisões Consolidadas

Pós-registro: Condicional (convite → dashboard, sem convite → onboarding)
CNPJ: Opcional no onboarding, obrigatório depois
Org Switcher: Topo do sidebar, substitui logo "Bens"
Login multi-org: Lembra última org, fallback /select-org
Backend: Better Auth org plugin + endpoints complementares
Escopo: Onboarding, switcher, select-org, accept-invitation
