**P1 finding — CSP allows `'unsafe-inline'` in `script-src`:**
This is required by Scalar (the API docs UI at `/api/docs`) for inline bootstrap scripts. It is a tradeoff between usability of the docs and strict CSP. Mitigations:

1. Accept as-is — the API has no user-generated HTML and no auth tokens in the response body, so inline script injection surface is minimal.
2. Scope the permissive CSP to `/api/docs` only via a Fastify `onRoute` hook, and apply a strict CSP elsewhere.
3. Serve Scalar docs as static prebuilt HTML and remove inline scripts entirely.

**P2 finding — Permissions-Policy absent:**
No Permissions-Policy header on the API. Low risk since the API serves JSON, not HTML, and browsers do not apply Permissions-Policy to XHR responses. Nice-to-have: set `Permissions-Policy: camera=(), microphone=(), geolocation=()` via helmet for defense in depth on any HTML response (e.g., `/api/docs`).

| Header                      | Present | Value                                      | Severity         |
| --------------------------- | ------- | ------------------------------------------ | ---------------- |
| Strict-Transport-Security   | yes     | `max-age=63072000`                         | **P2**           |
| X-Frame-Options             | yes     | `DENY`                                     | OK               |

| Content-Security-Policy     | **no**  | —                                          | **P1**           |
| Referrer-Policy             | yes     | `strict-origin-when-cross-origin`          | OK               |
| Permissions-Policy          | yes     | `camera=(), microphone=(), geolocation=()` | OK               |
| X-Vercel-Cache              | yes     | `HIT` (on `/`)                             | OK (info)        |
| Access-Control-Allow-Origin | yes     | `*`                                        | OK (public HTML) |

**P1 finding — CSP not set on the Next.js app:**
Vercel does not set CSP headers by default. Next.js apps need to configure CSP explicitly via:

- `next.config.js` -> `headers()` returning `{ key: 'Content-Security-Policy', value: '...' }` for `/:path*`
- Or Routing Middleware (`middleware.ts` / `proxy.ts`) setting the header per request

Without CSP, any XSS that slips through React's default escaping would run unconstrained. React 19 is strict by default, but a CSP adds defense in depth (especially for raw HTML injection code paths and third-party scripts loaded from CDNs).

Recommended minimum CSP for the app:

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'unsafe-inline' 'unsafe-eval';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  font-src 'self' data:;
  connect-src 'self' https://api.bensseg.com wss://api.bensseg.com;
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
```

The `'unsafe-inline'` + `'unsafe-eval'` on script-src is unfortunately required for Next.js 16 runtime + dev overlay. A stricter nonce-based CSP is achievable but requires migrating to middleware-based nonce injection — substantial work.

**P2 finding — HSTS missing `includeSubDomains`:**
`max-age=63072000` (2 years) is long, but the directive does not include `includeSubDomains`. If a subdomain of `bensseg.com` is ever added without TLS, browsers will not force HTTPS on it. Fix: set `max-age=63072000; includeSubDomains; preload` in `next.config.js` headers.

## 4. Positives worth highlighting

- Session token correctly stored as **httpOnly cookie** — not exposed to any XSS attack surface.
- No PII in `localStorage` / `sessionStorage` — the codebase correctly avoids storing user data client-side.
- Rate limiting (`100/min`) active on the API.
- CORS allowlist is explicit (`https://app.bensseg.com`), not wildcard.
- `X-XSS-Protection: 0` matches modern OWASP guidance (the legacy header is deprecated).
- HSTS preload-eligible on both endpoints (`max-age` >= 1 year on both).
- `X-Frame-Options: DENY` on the app prevents clickjacking entirely.
